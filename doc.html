Product & Logic Reference

PRISM이 실제로 하는 일

한 번도 안 써본 사람에게 설명하는 소개, 개발/기능 리뷰용 구조 정리, 그리고 설문 문항이 어떻게 MBTI 4글자로 계산되는지의 전체 로직 — 이 세 가지를 한 문서에 담았습니다.

① 프리즘이 뭐야 ② 기능/구조 리뷰 ③ 설문 → MBTI 로직 ④ 전체 문항
01

프리즘이 뭐야?

모르는 사람에게 설명한다고 생각하고 쓴 소개입니다.

한 줄로 말하면, "내가 생각하는 나"랑 "남들이 보는 나"가 얼마나 다른지 확인하는 서비스예요. 흔히 하는 MBTI 테스트인데, 나 혼자 푸는 게 아니라 친구·가족·연인·동료한테도 나를 관찰한 버전으로 풀게 시켜서 그 결과를 겹쳐 보여준다는 게 다릅니다.

1️⃣
내가 먼저 16문항을 푼다"나는 원래 이런 사람이야"라고 생각하는 나의 모습. 약 3분.
2️⃣
링크를 주변 사람에게 보낸다받은 사람은 나와의 관계(친구/가족/연인/동료)를 고르고, 그 관계에 맞춘 8문항으로 "이 사람은 이런 편이다"를 평가한다. 로그인도, 내 이름을 남기는 것도 없음 — 완전 익명.
3️⃣
상대가 만든 "응답 코드"를 붙여넣는다암호 같은 문자열 하나가 생성되고, 그걸 카톡으로 보내주면 내가 다시 붙여넣어서 결과에 합친다.
4️⃣
Identity Map이 열린다내가 생각한 유형과, 관계별로 다르게 보이는 유형을 나란히 보여주고, 어디서 가장 크게 어긋나는지("팩폭 지수")를 짚어준다.

예를 들어 나는 스스로 "T(사고형)"이라고 생각하는데, 연인은 나를 "F(감정형)"로 겪고 있다면 — 그 지점이 바로 "나는 모르는 나의 블라인드 스팟"으로 표시됩니다.

왜 재밌냐면

팩폭 지수

자기 인식과 타인 평균이 가장 크게 벌어지는 지점을 한 문장으로 요약해서 보여줌. "너 T인 줄 알았는데 다들 F로 본대" 같은 식.

관계마다 다른 나

같은 사람인데 친구 앞·가족 앞·회사에서 유형이 다르게 나올 수 있고, 그 변화 폭 자체를 "스펙트럼"으로 보여줌.

가면 지수

친밀도(얼마나 가까운 사이인지)와 인식 차이를 같이 봐서, 어느 관계에서 내가 가장 꾸밈없는지를 알려줌.

완전 익명 참여

증인(친구 등)은 로그인·이름 입력 없이 평가만 하고 코드만 돌려줌 — 누가 어떤 답을 했는지는 본인도 알 수 없게 설계됨.

기술 스택

프론트엔드

빌드 도구 없는 순수 HTML/CSS/Vanilla JS 단일 파일 (index.html). 프레임워크·번들러 없음.

백엔드

Supabase(Postgres + PostgREST). 클라이언트에서 anon key로 REST 엔드포인트 직접 호출.

호스팅

Vercel. 주의: GitHub 자동배포가 아니라 vercel --prod CLI 수동 배포 — git push만으로는 반영 안 됨.

다국어

헤더의 KOR/ENG 토글. 문구는 I18N_DATA/STR 언어별 테이블 + data-ko/data-en 속성으로 관리, 선택 언어는 localStorage에 저장.

데이터 모델 (Supabase 테이블 3개)

테이블주요 컬럼용도
prism_sessionsid, self_scores(jsonb), responses자가검사 1회당 세션 1개. 결과 페이지 URL의 ?s=가 이 id.
prism_responsessession_id, rel, scores, intimacy, ts관찰자(증인) 응답 1건당 1행. ts가 중복 추가 방지 키.
prism_feedbackmessage, created_at익명 한마디 피드백.

응답 코드 매커니즘

증인이 8문항을 다 풀면 {rel, scores, intimacy, ts} 객체를 JSON → btoa로 base64 인코딩해서 PRISM.xxxxx 형태의 문자열로 만듭니다(encodeResp). 이 코드는 Supabase에도 저장되고, 동시에 사람이 직접 복사해서 카톡 등으로 보낼 수도 있는 이중 경로로 설계되어 있어서, 네트워크 저장이 실패해도 코드 텍스트만 있으면 결과에 수동으로 합칠 수 있습니다(decodeResp → "관점 추가").

리뷰 포인트

확인 필요
Supabase anon key가 클라이언트 코드에 그대로 노출

공개 anon key 자체는 Supabase의 정상적인 사용 방식이지만, 실제 쓰기/읽기 권한은 테이블별 RLS(Row Level Security) 정책이 막아줘야 안전합니다. 세 테이블의 RLS 정책이 의도한 대로(익명 insert만 허용, 임의 조회/수정 차단 등) 설정돼 있는지 대시보드에서 확인 권장.

확인 필요
배포가 수동(CLI) 파이프라인

GitHub push ≠ 배포. 코드 수정 후 vercel --prod를 잊으면 라이브 사이트가 옛날 버전인 채로 남습니다. Vercel 프로젝트를 GitHub 연동으로 바꾸면 이 리스크가 사라집니다.

참고
인증 없음 — 세션은 URL 파라미터 + localStorage

로그인 개념이 없고, ?s=세션ID 링크와 브라우저 localStorage의 prism_session 키로 "내 결과"를 식별합니다. 링크나 브라우저 데이터를 잃으면 결과 접근 수단이 사라집니다.

참고
단일 파일 구조

빌드 단계가 없어 배포가 단순하지만, 문항/문구/로직이 한 파일(1300여 줄)에 모두 들어있어 규모가 커질수록 유지보수 비용이 커질 수 있는 트레이드오프입니다.

03

설문 → MBTI 매핑 로직

16(자가) / 8(관찰자)개의 리커트 문항이 어떻게 4개의 알파벳으로 압축되는지, 실제 계산식 그대로 설명합니다.

4개의 축

EI

에너지의 방향 — 사람들과 있을 때 채워지는가, 혼자 있을 때 채워지는가

E 외향I 내향

SN

정보를 받아들이는 방식 — 눈에 보이는 사실 중심인가, 숨은 의미·가능성 중심인가

S 현실N 직관

TF

판단의 기준 — 논리/사실이 먼저인가, 감정/관계가 먼저인가

T 사고F 감정

JP

생활 방식 — 미리 계획하고 정리하는가, 상황에 맞춰 유연하게 흘러가는가

J 계획P 유연

문항 하나하나에는 태그가 붙어있다

코드상 모든 문항은 {a, p, q} 세 가지 정보로 정의됩니다.

{ a:'EI', p:'E', q:'사람들과 어울리고 나면 오히려 에너지가 충전된다' }

a는 이 문항이 어느 축을 재는지(EI 중 하나), p는 "매우 그렇다"라고 답했을 때 어느 극으로 힘을 싣는 문항인지를 뜻합니다. 위 예시는 EI 축 문항인데 p:'E'이므로, 강하게 동의할수록 E 쪽으로 점수가 붙습니다. 같은 EI 축이라도 "혼자 있는 시간이 없으면 피로가 쌓인다"처럼 p:'I'인 문항도 있어서, 동의할수록 반대로 I 쪽에 힘이 실리도록 부호가 자동으로 뒤집힙니다.

5점 리커트 → 점수 변환

답변은 "전혀 그렇지 않다(0) ~ 매우 그렇다(4)"의 5단계. 이걸 scoreQ()가 아래 공식으로 -1 ~ +1 사이 값으로 바꿉니다.

v = (답변번호 - 2) / 2          // 0→-1, 1→-0.5, 2→0, 3→+0.5, 4→+1
if (p === a의 두번째 글자) v = -v // 문항의 힘의 방향이 축의 '음극'이면 부호 반전
축점수 = 그 축에 속한 모든 문항의 v 평균 × 100   // 반올림, -100~100 범위
문항"혼자 있는 시간이 없으면 피로가 쌓인다" (EI축, p=I)
내 답변3 = "그런 편이다"
1차 변환v = (3-2)/2 = +0.5
부호 반전p가 축의 두번째 글자(I) → v = -0.5
다른 EI 문항 3개와 평균예: (-0.5 -0.3 +0.2 -0.4)/4 = -0.25
최종 EI 축 점수-25 → 0 미만이므로 I

4글자 유형 만들기

4개 축 점수를 구했으면 typeFrom()이 각 축 부호만 보고 알파벳을 고릅니다 — 0 이상이면 첫 글자(E/S/T/J), 음수면 두번째 글자(I/N/F/P). 동점(0)은 첫 글자 쪽으로 처리됩니다.

type = (EI≥0 ? 'E':'I') + (SN≥0 ? 'S':'N') + (TF≥0 ? 'T':'F') + (JP≥0 ? 'J':'P')

자가검사 vs 관찰자검사

채점 로직은 완전히 동일합니다. 차이는 문항 세트뿐입니다 — 자가검사는 축당 4문항씩 총 16문항(모든 사람 공통), 관찰자검사는 축당 2문항씩 총 8문항인데 "친구/가족/연인/동료" 관계별로 문항 내용 자체가 다릅니다(예: 친구용은 "단톡방", 동료용은 "회의"처럼 그 관계에서 실제로 관찰 가능한 장면으로 각색). 관찰자 응답에는 마지막에 친밀도(1~5)가 별도로 붙는데, 이 값은 채점에는 관여하지 않고 Identity Map의 "가면 지수" 계산에만 쓰입니다.

Identity Map은 여기서 한 단계 더 간다

자가 점수와, 같은 관계의 응답 여러 개를 축별 평균낸 "타인 점수"를 나란히 놓고 축마다 |자가 - 타인| 차이를 봅니다. 차이가 클수록(코드 기준 gap > 25) "왜곡" 태그가 붙고, "팩폭 지수"는 그 중 가장 차이가 큰 축 하나를 골라 문장으로 요약합니다.
